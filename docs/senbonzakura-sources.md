# 千本樱实时演唱

- 作词、作曲：黒うさP / WhiteFlame。官方音乐页：https://whiteflame.jp/music/ 。
- 曲谱：https://vocaloader.app/sequences/3548 ，Kate 上传的「千本桜 VSQ」。
- 使用第 1、2 音轨 main vivid / sub 的完整主唱及第 9 轨应答声部，去重后 657 个事件、66 个不同音节。
- 基准速度约 154 BPM。裁掉首个歌词前约 32.57 秒和无歌词尾奏，保留全部歌词及内部休止。实时人声约 182.49 秒。
- `dist/playlist.js` 只加载 JSON 事件表，调用 `Mikutap.play(score,{engine:'sampler',muteBacktrack:true})`。没有整曲人声录音；歌曲自己的纯器乐伴奏由曲谱 accompaniment 字段指定，独立加载。
- `dist/sampler.js` 对每个音符使用 `MikutapVoice.getBuffer()` 返回的同一份原始音节 AudioBuffer，播放速度按 MIDI 音高变化。有声长音使用相位对齐的元音循环，短淡入淡出抑制边界爆音。没有振荡器或人声波形重建。
- `assets/basic/*.mp3` 是两位歌手的基础音节合并文件，用于减少请求；它们不包含歌曲。其他歌词音节读取独立 WAV。准备歌曲时并行缓存用到的 66 个音节。
- 调度与原作动画使用同一 AudioContext 时间轴。暂停、跳转和停止同时取消已排程的人声与器乐伴奏，恢复时使用同一个起点重建两路音频。原作节拍只临时锁定，不写入 BACKTRACK 偏好。
- 此路径保留单音节采样的机械连接感；未应用 VSQ 的专业音色参数及颤音，不声称达到商业歌声引擎的连续咬字。
- 未部署原始 VSQ、原始歌词文本、原始伴奏 WAV 或整曲人声 MP3。
- 专用伴奏取自 WhiteFlame 官方公开的千本桜カラオケ.wav（https://whiteflame.jp/music/），裁掉同样的 32.56964 秒前奏，编码为 128 kbps MP3，保留 182.48748 秒，与当前纯人声曲谱逐拍对齐。
- START 手动场景与首页歌单隔离；节目音频初始化不会合成一次 START 点击，不移动歌单 DOM。旧离线渲染工具仅供导出实验，不参与网站播放。

## 2026-10-30 发音衔接修正

- 原素材部分音节有约 40～90 毫秒前导空白，超过谱中最短的约 49 毫秒音符。缓存按能量检测跳过多余空白，同时保留辅音起始。
- `articulation: legato` 为同声部建立独立的发声时间表：辅音最多提前 45 毫秒，小于等于 160 毫秒的音间空隙延续元音，相邻音节约 26 毫秒交叉淡出。较长的换气、休止和间奏保留。
- 乐谱歌词事件、目标 MIDI 音高、伴奏时间轴均保持原值；暂停和跳转依旧取消并重建实际采样源。
- 手动初音区域按五声音阶分配音高，避免扩展库全为 C4 的低平效果；不把歌曲整体升调。该历史高频调整已撤销：当前原版发音直接使用原始片段。

## 独立应答与原版音源修正

- 第 9 轨独立的 ICBM（a i shi i i bi e mu）与 one-two-san-shi 共 17 个事件补回。第 8 轨为其低和声，未重复叠加；前面的主唱不替换，伴奏和时间轴不改动。
- 歌曲从开唱起约 10.909 秒进入 ICBM，约 12.37 秒结束；约 73.25 秒还有另一段应答。
- 原版 32 个 MP3 未重编码。手动模式原版音以原始速度和原始逐音量直接输出；歌曲仍需按目标 MIDI 变调并作短衔接。原版覆盖 21 个音节，其余继续使用完整扩展库。

## 洛天依强制版本与手动模式

- `senbonzakura-tianyi.json` 用普通话音节近似全部日语音节，保留 657 个事件、音高、时长、ICBM、应答段与同一个伴奏。只替换 voice / syllable，保留 sourceSyllable 供核查，不是中文歌词翻译。
- 首页选择歌手时实际加载相应版本。播放或暂停时切换均保留进度与暂停状态；用 owner 标识避免影响显式调用程序乐谱的发声。
- START 完全回到原版 32 区输入，删除 46 区 pointer 覆盖层。洛天依手动也固定对应 32 片段，与其程序完整声库分开。

## 固定音源的准备缓存

- 歌单显式启用演奏计划缓存，按原曲谱对象、音源和演奏方式复用采样缓冲及编译后的事件；谱面内容变化自动失效。普通程序 play 默认仍按传入谱面处理。
- 首播后静默准备另一位歌手，预热不会创建发声节点、修改当前播放状态或位置。并发请求共享同一份准备任务，失败后允许重试。
- 已准备完成时不进入 loading 状态，也不显示“准备中”。首次进入页面或另一音源尚未加载完，仍需真实的下载、解码过程。
